# 더빙 작업실 (저장소 이름: Project_H)

스크립트 기반 게임의 **대사·녹음 대본·음성 검수 상태를 씬 단위로 관리**하는 정적 웹 페이지입니다. 여러 작품을 한 곳에서 다루며, 현재 작품은 `suikoden1`(환상수호전 1, **기본 작품**)과 `seohee`(가제)입니다. 페이지 이름은 2026-11-12에 "Project_H 통합관리"에서 "더빙 작업실"로 바꿨습니다(저장소·폴더 이름은 GitHub Pages 주소와 PC 경로 때문에 그대로).

> 다음 작업자(AI)는 이 문서만 읽고 바로 시작할 수 있도록 적었습니다.

## 만든 의도

- 원래 엑셀 한 파일로 대사·대본을 관리했고, 번역·수정을 AI에게 맡길 때마다 엑셀 전체를 읽히고 다시 쓰게 해서 **시간과 토큰이 많이 들었습니다.**
- 만든 음성 파일이 많아져서 **특정 대사의 음성을 바로 찾아 확인하기 어려웠습니다.**
- 장기적으로 이 데이터를 게임 제작에도 쓸 예정입니다.

## 작업 방식 (중요)

- **수정은 전부 AI가 합니다.** 사용자는 페이지로 보고, 대화로 수정을 요청하고, 결과를 확인만 합니다. 흐름은 **요청 → AI가 바로 적용 → 사용자가 대사집 화면과 채팅으로 확인 → 이상하면 "되돌려줘"** 입니다. 승인 단계와 별도의 변경 내역 화면은 없고, 페이지에는 대사 직접 편집 기능이 없습니다(행 상세 패널 제거).
- AI는 파일을 통째로 읽지 말고 **`tools/scene.js`로 필요한 씬·필드만 읽고, 바뀐 행만 반영**하세요. 엑셀을 다시 쓰지 않습니다.
- 수정할 때는 **항상 `set`을 쓰고 `--note "수정 사유"`를 붙이세요.** 수정 전·후가 `data/changes/`에 자동 기록되어 `revert`로 정확히 되돌릴 수 있습니다(수정 전·후 내용은 `log --detail`로 확인). 파일을 직접 고치면 기록이 남지 않습니다.
- 사용자가 어느 행인지 알려줄 때는 씬 ID와 `원본 행` 번호(엑셀 행 번호)나 `id`(예: `01姉_00_01.ks#22`)를 말합니다. `--ids`에는 마지막 `id`를 쓰세요. 되돌릴 때는 `revert <씬ID> --last` 또는 `log`에서 찾은 `--batch <묶음ID>`를 씁니다.
- 사용자는 집과 회사 PC를 오가며 작업합니다. **대본 데이터만 GitHub**에 올리고, **음성·CG는 집 PC에만** 둡니다(저장소에 올리지 않음). 회사에서는 대본 수정 요청과 검수만 합니다.

## 번역·대사 검수 기준

### 기본 원칙

- 번역 흐름은 **일본어 원문 → 영어 번역 → 한국어**입니다. 영어 문장을 그대로 직역하지 말고 일본식 표현과 어순, 장면 문맥을 고려해 자연스러운 한국어로 재구성합니다.
- 현재 데이터에는 일본어 원문 열이 없으므로, 영어 원문과 장면의 앞뒤 흐름을 기준으로 일본식 번역투를 추정해 수정합니다. 원문 대사는 비교할 수 있도록 보존하고 한국어 대사만 고칩니다.
- 장면의 상황, 앞뒤 문맥, 인물 관계와 성격을 먼저 파악합니다. 원문의 의미를 빠뜨리거나 원문에 없는 내용을 과도하게 추가하지 않습니다.
- 인물 대사는 자연스러운 구어체로, 나레이션은 끊기지 않는 서술체로 작성합니다. 번역투 어순, 주어·목적어 누락, 문장 중단을 특히 확인합니다.
- 서희뿐 아니라 준형·나레이션·부모님·주변 인물까지 모든 화자를 검수합니다.
- 일반씬은 자연스러운 일상 대화를 우선합니다. 행위씬은 도입·전희·주요 행위·절정 전·절정·사정·사정 후의 단계와 감정 변화에 맞춰 표현 강도를 조절합니다.
- 첫 행위씬 이후 경험이 쌓일수록 서희의 말투는 조금씩 대담하고 적극적으로 변합니다. 다만 갑자기 성격이 바뀌거나 원문보다 지나치게 노골적인 표현을 임의로 넣지 않습니다.
- 직접적인 단어는 문맥상 필요하면 사용할 수 있지만, 전체적으로는 조금 순화된 수준을 유지합니다.
- 서희의 행위씬 한국어 대사를 수정하면 `recordingScript`에도 같은 내용을 반영합니다. 현재 준형은 음성 대상에서 제외하며, 나머지 인물은 음성 대상이라는 점을 고려합니다.
- `prompt`는 녹음·음성 생성용 지시문을 나중에 씬 단위로 일괄 입력하기 위한 별도 필드입니다. 대사나 녹음용 대본과 섞지 않습니다.

### 신음·의성어 기준

- `Nhah`, `Ngah`, `Mphagh` 같은 영문 음절을 그대로 옮기지 않습니다. 당시의 호흡, 감정, 입의 상태에 맞춰 한국어에서 실제 발음 가능한 소리로 다시 구성합니다.
- `응하`, `응하아`, `응아`는 사용하지 않습니다. 기본 신음은 `하응`, `아응`, `으응`, `하아`, `아아` 계열을 사용합니다.
- 입이 막힌 상황은 `음`, `으음`, `음읍`, `흐읍`처럼 구분합니다.
- `음파그`, `응가그`, `가그`, `게그`, `가글`, `철럽`처럼 외국어 음절을 기계적으로 옮긴 표현은 사용하지 않습니다.
- 효과음은 상황에 따라 `쪽`, `음쪽`, `츄릅`, `철퍽`, `할짝`, `꿀꺽`, `컥` 등을 사용하되 지나치게 반복하지 않습니다.
- 장면이 고조될수록 호흡과 신음의 강도를 자연스럽게 변화시키고, 같은 소리만 기계적으로 반복하지 않습니다.
- 대사와 녹음용 대본의 표기를 동일하게 유지하며, 수정 후 금지 표현 잔존 여부와 두 필드의 불일치를 검사합니다.

## 사용법

### 페이지 보기
`index.html`을 브라우저로 열면 됩니다(서버 불필요). 상단 `작품` 목록으로 작품을 바꾸고, 씬을 고르면 그 씬 파일만 불러옵니다. 주소에 `?work=<작품ID>`를 붙여도 됩니다. 주소에 작품이 없으면 `work.json`에 `"default": true`가 있는 작품(현재 `suikoden1`)이 열립니다(바꾼 뒤 `node tools/work.js sync`).

- **오른쪽 패널은 프롬프트 관리/삽입 전용**입니다. 표의 줄을 누르면(체크박스 칸이 아니어도) 그 줄이 프롬프트 대상으로 체크되고 다시 누르면 해제됩니다. 녹음용 대본이 없는 줄은 체크되지 않습니다.
- **영어 원문 열은 기본으로 숨김**이고, 필터 줄의 `영어 원문 표시`를 켜면 표에 나타납니다(선택은 이 브라우저에 기억됨). 한국어 대사가 가장 넓게 표시되며, 숨겨진 열은 검색 대상에서도 제외됩니다. 일본어 원문 열이 생기면 `app.js`의 `fields`와 `SOURCE_COLUMNS`에 추가하면 같은 방식으로 숨김·표시됩니다.
- AI가 수정한 내용을 반영하려면 페이지를 새로고침하세요. (수정 전·후 비교 화면은 없습니다. 필요하면 GitHub Desktop의 변경 비교를 쓰세요.)

### 음성 재생
- 표의 복사 열 맨 위 `한 ▶`는 한국어 더빙, `일 ▶`는 일본어 원본을 재생합니다(다시 누르면 정지). 파일이 없는 줄은 해당 버튼이 흐리게 꺼집니다. 음성은 버튼을 눌러야만 재생되며 페이지 열기·새로고침 때 자동 재생하지 않습니다.
- 선택 줄의 `▶ 연속 재생 (N)`은 지금 보이는 줄(단계 탭·필터 반영)의 음성을 위에서부터 차례로 재생합니다. 단계 탭을 고르면 그 단계만 재생합니다.
- 줄 ↔ 음성 연결표는 `works/<작품ID>/data/voices.js`이며, 게임 스크립트에서 다시 만들 수 있습니다:
  `node tools/voicemap.js --scripts "C:\Games\Onee-chan no Yuuwaku\work\patch_en"`
- 음성 파일은 저장소에 올리지 않습니다(`.gitignore`의 `voice/`). 집 PC에서는 `Project_H\voice`를 실제 음성 폴더로 연결해 둡니다(한 번만, PowerShell):
  `New-Item -ItemType Junction -Path "C:\Games\Onee-chan no Yuuwaku\Project_H\voice" -Target "C:\Games\Onee-chan no Yuuwaku\ko\voice"`
  회사 PC처럼 음성 폴더가 없으면 재생 버튼이 모두 꺼진 상태로 보일 뿐 다른 기능에는 영향이 없습니다.

- 일본어 원본은 `arc\voice.xp3`에서 `C:\Games\Onee-chan no Yuuwaku\ko\voice_ja`로 추출해 둡니다. 저장 서버가 `/media/voice-ja/<음성ID>.ogg`로 제공하며 Git에는 올리지 않습니다. 다른 위치를 쓰려면 `PROJECT_H_ORIGINAL_VOICE_DIR`을 지정합니다.

### 모바일 보기
폭 820px 이하(휴대폰)에서는 자동으로 모바일 레이아웃이 적용됩니다(`styles.css` 맨 아래 `@media (max-width:820px)` 블록, 데스크톱 화면은 그대로).
- 표는 줄마다 **카드**로 바뀝니다: 화자·행 번호, 한국어 대사, 프롬프트, 녹음용 대본, 메모, 복사·재생 버튼 순. ID·종류·씬/단계 정보 칸은 카드에서 뺍니다. 카드를 누르면 체크가 켜지고 꺼지는 동작은 같습니다.
- 선택 줄은 화면 위에 붙어 가로로 밀어 볼 수 있고, 맨 앞의 `☰ 씬` 버튼이 **씬 목록 서랍**을, `프롬프트 (선택 수)` 버튼이 **프롬프트 패널(아래 시트)**을 엽니다. 어두운 바깥 영역이나 `프롬프트 패널 닫기`, Esc로 닫고, 씬을 고르면 서랍이 자동으로 닫힙니다.

### 🚩 검수 표시 (이상한 줄 체크 + 메모)
대사가 어색하거나 이상한 줄에 🚩를 누르고 어디가 이상한지 메모를 남깁니다. 나중에 AI가 이 목록을 보고 고칩니다. 휴대폰에서도 같습니다(카드의 🚩 버튼, 메모 입력칸).
- 표시는 줄의 `review` 필드입니다. 비어 있으면 정상, 글자가 있으면 검수 필요 + 메모(메모 없이 🚩만 누르면 `검수 필요`). 기존 `메모`(`memo`) 칸과는 별개입니다.
- **저장 서버로 열었을 때(집 PC)**: 🚩를 누르는 즉시 데이터 파일에 저장되고 변경 기록이 남습니다. 커밋·푸시하면 GitHub에도 올라갑니다.
- **서버 없이 열었을 때(폰의 GitHub 주소 등)**: 표시는 **그 브라우저에만** 저장됩니다(맨 위 상태 칸에 `🚩 N건 (이 브라우저)`). 브라우저 데이터를 지우면 사라지고, 다른 기기에서는 보이지 않습니다.
- 전달 방법: 선택 줄의 `🚩 검수 목록` → 대화상자의 `복사` → AI에게 붙여 넣기. 집 PC(저장 서버)에서는 같은 대화상자에 복사해 온 목록을 붙여 넣고 `붙여 넣은 목록 반영`을 누르면 데이터 파일에 저장됩니다. 전달이 끝나면 폰에서 `내 표시 비우기`로 지웁니다(안 지우면 AI가 고쳐서 표시가 사라진 뒤에도 폰에는 계속 남아 보입니다).
- 필터 `🚩 검수 표시만`, 씬 목록의 `🚩N`, 현황 줄의 `🚩 검수 표시`로 남은 건수를 봅니다.
- AI·작업자용 명령:
  ```bash
  node tools/review.js --work seohee list [<씬ID>] [--count]          # 표시된 줄 목록 (JSON), --count 는 씬별 개수만
  node tools/review.js --work seohee import 검수목록.json [--dry]       # 복사해 온 목록을 파일에 반영 (- 는 표준입력)
  node tools/review.js --work seohee resolve H1 --ids <id,id> | --rows 22-30 | --all [--note "사유"]   # 고친 줄의 표시 지우기
  ```
  줄 내용은 `scene.js set`으로 고치고, 고친 줄은 `resolve`로 표시를 지웁니다(패치에 `"review":""`를 같이 넣어도 됩니다). 모두 변경 기록에 남아 `scene.js revert`로 되돌릴 수 있습니다.

### AI·작업자용 도구
작품이 하나뿐이면 `--work`를 생략할 수 있고, **둘 이상이면 반드시 지정**해야 합니다.

```bash
node tools/scene.js --work seohee list                                   # 씬별 행 수·진행률
node tools/scene.js --work seohee get N1 --fields id,korean --limit 20   # 필요한 필드만 조회
node tools/scene.js --work seohee get H13 --empty prompt --fields id,speaker,korean,prompt  # 프롬프트가 빈 행
node tools/scene.js --work seohee get N1 --empty korean --fields id,english   # 한국어가 빈 행
node tools/scene.js --work seohee get H3 --from 3000 --to 3100 --tsv     # 엑셀 행 번호 범위
node tools/scene.js --work seohee set N1 patch.json --dry                # 수정 미리 검증 (파일 변경 없음)
node tools/scene.js --work seohee set N1 patch.json --note "말투 통일"    # 바뀐 행만 반영 + 수정 사유 기록
node tools/scene.js --work seohee log N1                                 # 변경 묶음 목록 (본문 없이 요약)
node tools/scene.js --work seohee revert N1 --last                       # 가장 최근 변경 되돌리기
node tools/scene.js --work seohee revert N1 --batch b20261111-130500 --ids <id1,id2>   # 특정 묶음(의 일부 행) 되돌리기
```

- `patch.json`: `[{"id":"…","korean":"수정한 대사"}, …]` — 바뀐 필드만 적습니다. 여러 행에 `prompt`를 넣은 배열을 만들어 `set`하면 프롬프트를 한 번에 반영할 수 있습니다.
- 수정 가능 필드: `kind`, `speaker`, `english`, `korean`, `recordingScript`, `prompt`, `memo`, `voice`, `review`(🚩 검수 표시). `id`·`rowNumber`·`phaseId`와 씬 정보는 바꿀 수 없고, 잘못된 ID나 필드가 하나라도 있으면 **아무것도 적용하지 않습니다.**
- 반영하면 변경 기록이 남고(`set` 결과의 `batch`가 묶음 ID), `index.js`의 개수·진행 통계가 자동으로 다시 계산됩니다.
- `revert`는 기록의 수정 전 값으로 복구합니다. 그 뒤에 다른 수정이 있었던 항목은 건드리지 않고 `conflicts`로 알려주며, 일부만 되돌려진 묶음은 `--last`로 남은 항목을 다시 되돌릴 수 있습니다. `--dry`로 미리 확인할 수 있습니다.
- `log`는 기본적으로 본문 없이 요약만 출력합니다(`--detail`을 줘야 수정 전·후가 나옴).

## 프롬프트 선택·일괄 삽입 (구현됨)

`recordingScript`는 성우나 음성 모델이 읽을 **녹음용 대본**이고, `prompt`는 감정·톤·속도 등을 지시하는 **별도 프롬프트**입니다. 두 값은 합치지 않습니다. 이 기능은 대본이 있는 행에 템플릿 프롬프트를 한꺼번에 넣고 지우기 위한 것입니다.

**화면 사용 순서** (대사집 화면, 필터 줄 아래의 선택 줄)

1. 표 맨 앞 체크박스로 행을 고릅니다. **`recordingScript`가 있는 행만** 선택할 수 있고 없는 행은 체크박스가 비활성입니다. 표 머리 체크박스는 화면에 표시된 대본 행 전체를 켜고 끕니다.
2. 선택 줄의 버튼으로 한 번에 고를 수도 있습니다. 누르면 선택이 그 범위로 **바뀝니다**.
   - `표시된 행 전체`: 현재 필터·단계 탭에 보이는 행만 (숨겨진 행 제외)
   - `현재 단계 전체`: 현재 단계의 모든 행 (**필터로 숨겨진 행 포함**, 단계 탭을 고른 경우에만)
   - `현재 씬 전체`: 씬의 모든 행 (**필터·단계와 관계없이 숨겨진 행 포함**)
   - 선택 개수는 항상 `선택 N행 (표시 a · 필터로 숨김 b)`로 보입니다. **필터를 바꿔도 선택은 유지되고, 씬을 바꾸면 해제됩니다.**
3. 오른쪽 `프롬프트 관리/삽입` 패널(항상 열려 있음)에서 템플릿 버튼을 하나 이상 켜고 작업을 정합니다. 여러 개를 켜면 누른 순서대로 `[내용1, 내용2, 내용3]` 형식(쉼표+공백 구분, 대괄호)으로 합쳐집니다.
   - `빈 칸만 적용`: 이미 프롬프트가 있는 행은 그대로 둠
   - `기존 값 교체`: 선택 행을 모두 이 템플릿으로 바꿈 — 기존 프롬프트가 사라지는 행 수를 보여 주고 **확인란을 체크해야** 진행됨
   - `선택 행 프롬프트 삭제`: 프롬프트가 있는 행만 지움 — 대상 행 수를 보여 주고 확인란 체크 필요
4. (서버 없이) `AI 작업 요청 복사`를 눌러 채팅에 붙여넣으면 AI가 `tools/prompt.js` 명령을 실행해 **저장소 데이터에 반영**합니다(페이지는 읽기 전용이라 파일을 직접 바꾸지 않고, 브라우저 로컬 수정도 건드리지 않습니다). 반영 뒤 페이지를 새로고침하면 `프롬프트` 열에 나타납니다.

**집에서 직접 고칠 때: 저장 서버** — 녹음을 돌려 보고 프롬프트를 직접 고치고 싶을 때는 폴더의 `저장서버 켜기.bat`을 더블클릭하세요(또는 `node tools/server.js --open`). 브라우저가 `http://127.0.0.1:8787/`로 열리고, 상단에 `저장 서버 연결됨`이 보이면 아래가 켜집니다.
- `프롬프트 관리/삽입`의 `지금 적용 (파일에 저장)` → 선택한 행에 바로 채우거나 지웁니다. AI에게 붙여넣는 단계가 필요 없습니다.
- 페이지에는 템플릿 추가·수정 기능이 없습니다. 템플릿은 `prompts.js`를 직접 고치거나 `tools/prompt.js template set|remove`로 관리합니다(이미 적용한 행은 바뀌지 않음).
- 서버는 이 컴퓨터(127.0.0.1)에서만 열리고 다른 사이트의 저장 요청은 거부합니다. 창을 닫으면 꺼지고, 그러면 페이지는 예전처럼 읽기 전용(브라우저 로컬 수정)이 됩니다. 되돌리기는 AI에게 요청하거나 `scene.js revert`를 씁니다.
- **왜 서버(.bat)가 필요한가:** 브라우저 페이지는 보안상 PC의 파일을 직접 쓸 수 없어서, 파일에 대신 써 주는 도우미가 필요합니다. 서버가 꺼져 있으면 `지금 적용` 버튼이 보이지 않고 `AI 작업 요청 복사`만 있으며, 그 버튼은 요청 문장을 복사할 뿐 파일에는 아무것도 저장하지 않습니다. 저장이 되는지는 상단의 `저장 서버 연결됨` 표시로 확인합니다.
- AI에게 요청하는 방식이면 서버는 필요 없습니다(AI가 직접 파일에 씀). 서버는 AI 없이 집에서 화면으로 직접 고치고 싶을 때만 켜는 선택 사항입니다.- 회사 PC나 AI에게 맡길 때는 서버 없이 `AI 작업 요청 복사`를 씁니다. 저장된 파일은 GitHub Desktop에서 커밋·푸시해야 다른 PC에 반영됩니다.
복사되는 요청은 이런 모양입니다(행 번호는 엑셀 행 번호 범위, 대본이 없는 행은 도구가 알아서 건너뜀).

```
프롬프트 일괄 적용 요청
- 작품 seohee · 씬 N1 · 선택 12행 (실제 변경 예정 10행)
- 템플릿 「일상 대화」(daily) · 빈 칸만 적용

node tools/prompt.js --work seohee apply N1 --template daily --mode fill --rows 22-30,35
node tools/prompt.js --work seohee apply N1 --template soft,shy --mode fill --rows 22-30   # 여러 템플릿: 쉼표 순서대로 [내용1, 내용2] 형식
```

**AI가 할 일:** 요청 안의 명령을 그대로 실행하고 결과 JSON(`changedRows`, `skippedHasValue`, `batch` 등)을 사용자에게 알려줍니다. 되돌릴 때는 `node tools/scene.js --work <작품ID> revert <씬ID> --last`입니다(프롬프트 변경도 같은 변경 기록에 남음). 먼저 확인하고 싶으면 명령 끝에 `--dry`를 붙입니다.

**템플릿 관리:** 템플릿은 작품별 `works/<작품ID>/data/prompts.js`에 있으며 페이지 목록에 그대로 나타납니다. 분류 탭도 작품마다 정할 수 있습니다: `prompts.js`의 `"groups":[["키","탭 이름"], …]` (없으면 기본 탭 행위·단계·흥분도·추가 감정, `suikoden1`은 감정·말투·속도·호흡·상황). 추가·수정·삭제는 채팅으로 AI에게 요청하고, AI는 아래 명령을 씁니다. 지금 들어 있는 6개(일상 대화·밝고 경쾌하게·부드럽게 속삭이듯·나레이션 담담하게·놀람·당황·쓸쓸하고 가라앉은 톤)는 **임의의 예시**이니 실제 쓸 내용으로 바꾸세요.

```bash
node tools/prompt.js --work seohee templates                                            # 템플릿 목록
node tools/prompt.js --work seohee template set daily --name "일상 대화" --text "프롬프트 내용"   # 추가·수정
node tools/prompt.js --work seohee template remove daily
node tools/prompt.js --work seohee apply N1 --template daily --phase N1-P1 --mode replace --dry  # 단계 전체 교체 미리보기 (--rows / --phase / --all 중 하나)
node tools/prompt.js --work seohee clear N1 --all                                       # 씬의 대본 행 프롬프트 모두 삭제
```

`--note "사유"`를 생략하면 `프롬프트 빈 칸 적용: <템플릿 이름>` 같은 기본 사유가 기록됩니다. 템플릿에 변수(화자 이름 등)를 넣는 기능은 아직 없고, 문장 그대로 `prompt`에 들어갑니다.

### 사용자와 일하는 방식 (환수 작업에서 정해진 것)

- 사용자가 고른 표현: 가축 우리 → **마구간**, 애송이 → **꼬맹이**, 술법 → **마법**, 형씨 → **여러분**. 테드의 "평생 소원"은 1002000168에만(테드가 죽을 때 다시 나오는 말). 1002000158/160의 일본식 표현은 사용자 선택으로 유지.
