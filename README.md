### 새가족 (newfamily) — 1·2부 대사 완료, 녹음용 대본 입력됨
- **대사(1부 180줄·2부 192줄)**: 사용자가 전부 검수했고 **이상 없음(완료)**. 폰에서 표시한 🚩 28건(+보류 9건)은 모두 반영했고 **남은 🚩 0건**.
- **나레이션**: 1부 후반(12줄)·2부(26줄) 윤문 + 복장 수정 + 2차 윤문(9줄) 완료. 1부 초반은 기준 문체라 거의 그대로. 손대지 않은 구간은 필요하면 새 문체 기준(⑧~⑯)으로 다시 점검 가능(범위는 사용자와 정함).
- **복장 설정 확정**(위 새가족 항목 참고): 엄마 회상 = 흰 오프숄더 드레스 / 귀가 = 검은 정장 + 딱 붙는 치마, 미소 = 1·2부 모두 짧은 흰 티셔츠 + 핑크 돌핀 팬츠(묘사 겹치지 않게), 소영 변경 없음.
- **녹음용 대본(`recordingScript`)**: 대사와 **똑같이 입력 완료 — 1부 44줄·2부 63줄(합계 107줄)**. **주인공(진선후)과 나레이션은 비움**(주인공 녹음 안 함, 나레이션은 주인공 시점이라 녹음 대상으로 보지 않음 — **나레이션도 녹음할지는 사용자 확인 필요**). 대본을 새로 고치면 `korean`과 같게 유지.
- **프롬프트(ElevenLabs 태그)**: 녹음 대본 107줄 모두 입력됨 — 인물 기본 + 감정 + 소리/상황 공식, 단역은 감정만, 상상 장면 4줄은 시험 적용. 설계·규칙은 새가족 항목의 `프롬프트 제작 설계`. **감정은 초안이라 녹음해 보고 조정 필요**, 인물 태그 2안(나이대)은 버튼만 추가해 둔 상태.
- **도구**: 줄 추가·삭제(`scene.js insert/delete`) 만듦(번호가 이어지는 씬만, 새가족에서 사용). 엑셀 원본은 없고 이 저장소 데이터가 유일한 원본.
- **스토리 방향 메모**(주인공 심리 변화 4단계, 모든 여성 인물과 관계가 이어지는 전개)는 새가족 항목 끝에 있음. **언제·어떤 순서로 쓸지는 미정**.
- **다음 후보(사용자가 정함)**: 나레이션 녹음 여부 결정 → 프롬프트 템플릿 조정(1차 적용 완료, 녹음해 보고 수정) → 음성 녹음·자르기(설계는 `사용법 > 음성 녹음·자르기`에 있고 **도구는 아직 없음**: 자르기·검사·앞뒤 무음 붙이기 스크립트를 만들면 됨) → 음성 연결 → 3편 집필(스토리 메모 참고).

## 만든 의도

- 원래 엑셀 한 파일로 대사·대본을 관리했고, 번역·수정을 AI에게 맡길 때마다 엑셀 전체를 읽히고 다시 쓰게 해서 **시간과 토큰이 많이 들었습니다.**
- 만든 음성 파일이 많아져서 **특정 대사의 음성을 바로 찾아 확인하기 어려웠습니다.**
- 장기적으로 이 데이터를 게임 제작에도 쓸 예정입니다.

## 작업 방식 (중요)

- **수정은 전부 AI가 합니다.** 사용자는 페이지로 보고, 대화로 수정을 요청하고, 결과를 확인만 합니다. 흐름은 **요청 → AI가 바로 적용 → 사용자가 대사집 화면과 채팅으로 확인 → 이상하면 "되돌려줘"** 입니다. 승인 단계와 별도의 변경 내역 화면은 없고, 페이지에는 대사 직접 편집 기능이 없습니다(행 상세 패널 제거).
- AI는 파일을 통째로 읽지 말고 **`tools/scene.js`로 필요한 씬·필드만 읽고, 바뀐 행만 반영**하세요. 엑셀을 다시 쓰지 않습니다.
- 수정할 때는 **항상 `set`을 쓰고 `--note "수정 사유"`를 붙이세요.** 수정 전·후가 `data/changes/`에 자동 기록되어 `revert`로 정확히 되돌릴 수 있습니다(수정 전·후 내용은 `log --detail`로 확인). 파일을 직접 고치면 기록이 남지 않습니다.
- 사용자가 어느 행인지 알려줄 때는 씬 ID와 행 번호(`원본 행` 열)나 `id`(예: `01姉_00_01.ks#22`, `EP1#12`)를 말합니다. **줄을 추가·삭제한 작품(새가족)은 행 번호가 다시 매겨지므로 `id`로 가리키세요.** `--ids`에는 마지막 `id`를 쓰세요. 되돌릴 때는 `revert <씬ID> --last` 또는 `log`에서 찾은 `--batch <묶음ID>`를 씁니다.
- 사용자는 집과 회사 PC를 오가며 작업합니다. **대본 데이터만 GitHub**에 올리고, **음성·CG는 집 PC에만** 둡니다(저장소에 올리지 않음). 회사에서는 대본 수정 요청과 검수만 합니다.

works/
  works.js                 작품 목록 (tools/work.js sync 로 자동 생성)
  <작품ID>/                작품 폴더 (suikoden1, seohee, newfamily)
    work.json              작품 ID·표시 이름·표시 옵션(기본 작품, CG/일본어 음성 버튼 숨김 등)
    data/index.js          메타, 화자 목록, 씬 목록(종류·설명·단계·진행 통계)
    data/scenes/<씬ID>.js  씬별 행 목록 (한 줄에 한 행)
    data/changes/<씬ID>.js 씬별 AI 변경 기록 (수정 전·후, 도구가 자동 생성 — 수정이 생기면 만들어짐)
    data/prompts.js        프롬프트 템플릿 목록 (페이지의 저장 서버 또는 tools/prompt.js 로 관리)

tools/                     조회·수정·작품 관리 도구 (Node.js), server.js = 저장 서버

- 행 필드: `rowNumber`(행 번호; 작품마다 의미가 다름 — 서희는 엑셀 행 번호, 새가족은 줄 추가·삭제 때 다시 매기는 일련번호), `id`(작품 안에서 고유), `kind`, `speaker`, `english`, `korean`, `recordingScript`, `prompt`, `memo`, `voice`(✓ = 음성 체크), `phaseId`, `review`(🚩 검수 표시·메모, 비어 있으면 파일에 쓰지 않음)
- 씬 종류·설명·단계명·단계 상세는 `index.js`의 씬 정보에 한 번만 저장됩니다.

## 사용법

### 페이지 보기
`index.html`을 브라우저로 열면 됩니다(서버 불필요). 상단 `작품` 목록으로 작품을 바꾸고, 씬을 고르면 그 씬 파일만 불러옵니다. 주소에 `?work=<작품ID>`를 붙여도 됩니다. 주소에 작품이 없으면 `work.json`에 `"default": true`가 있는 작품(현재 `suikoden1`)이 열립니다(바꾼 뒤 `node tools/work.js sync`).

- **오른쪽 패널은 프롬프트 관리/삽입 전용**입니다. 표의 줄을 누르면(체크박스 칸이 아니어도) 그 줄이 프롬프트 대상으로 체크되고 다시 누르면 해제됩니다. 녹음용 대본이 없는 줄은 체크되지 않습니다.
- **영어 원문 열은 기본으로 숨김**이고, 필터 줄의 `영어 원문 표시`를 켜면 표에 나타납니다(선택은 이 브라우저에 기억됨). 한국어 대사가 가장 넓게 표시되며, 숨겨진 열은 검색 대상에서도 제외됩니다. 일본어 원문 열이 생기면 `app.js`의 `fields`와 `SOURCE_COLUMNS`에 추가하면 같은 방식으로 숨김·표시됩니다.
- **표는 `복사` 열까지만 보이고**, 그 오른쪽의 씬·단계 정보 열(씬 종류·씬 ID·씬 상세·단계 ID·단계·단계 상세)은 접혀 있습니다. 머리글 맨 끝 `▶` 버튼으로 펼치고 `◀`로 접습니다(선택은 이 브라우저에 기억). `메모`·`음성` 열은 2026-11-12에 표에서 뺐습니다 — 데이터(`memo`, `voice` ✓)는 그대로이고, 음성 확정 여부는 `전체 음성 상태` 필터와 진행 막대로 봅니다. 대사 ID로 씬을 찾으려면 왼쪽 씬 목록 검색에 ID를 넣고, 화자 필터에는 `화자 있음`/`화자 없음` 항목이 있습니다.
- AI가 수정한 내용을 반영하려면 페이지를 새로고침하세요. (수정 전·후 비교 화면은 없습니다. 필요하면 GitHub Desktop의 변경 비교를 쓰세요.)
- 폰이나 다른 PC에서 예전 화면이 보이면 브라우저가 파일을 저장해 둔 것입니다. `index.html`의 `?v=` 값을 바꿔 올리거나, 주소 끝에 새 `?v=숫자`를 붙여 여세요.

### 음성 재생
- 표의 복사 열 맨 위 `한 ▶`는 한국어 더빙, `일 ▶`는 일본어 원본을 재생합니다(다시 누르면 정지). 파일이 없는 줄은 해당 버튼이 흐리게 꺼집니다. 음성은 버튼을 눌러야만 재생되며 페이지 열기·새로고침 때 자동 재생하지 않습니다.
- 선택 줄의 `▶ 연속 재생 (N)`은 지금 보이는 줄(단계 탭·필터 반영)의 음성을 위에서부터 차례로 재생합니다. 단계 탭을 고르면 그 단계만 재생합니다.

### 🚩 검수 표시 (이상한 줄 체크 + 메모)
대사가 어색하거나 이상한 줄에 🚩를 누르고 어디가 이상한지 메모를 남깁니다. 나중에 AI가 이 목록을 보고 고칩니다. 휴대폰에서도 같습니다(카드의 🚩 버튼, 메모 입력칸).
- 표시는 줄의 `review` 필드입니다. 비어 있으면 정상, 글자가 있으면 검수 필요 + 메모(메모 없이 🚩만 누르면 `검수 필요`). `memo` 필드는 데이터에만 남아 있고 페이지에는 표시하지 않습니다(2026-11-12 열 삭제).
- **저장 서버로 열었을 때(집 PC)**: 🚩를 누르는 즉시 데이터 파일에 저장되고 변경 기록이 남습니다. 커밋·푸시하면 GitHub에도 올라갑니다.
- **서버 없이 열었을 때(폰의 GitHub 주소 등)**: 표시는 **그 브라우저에만** 저장됩니다(맨 위 상태 칸에 `🚩 N건 (이 브라우저)`). 브라우저 데이터를 지우면 사라지고, 다른 기기에서는 보이지 않습니다.
- 전달 방법: 선택 줄의 `🚩 검수 목록` → 대화상자의 `복사` → AI에게 붙여 넣기. 집 PC(저장 서버)에서는 같은 대화상자에 복사해 온 목록을 붙여 넣고 `붙여 넣은 목록 반영`을 누르면 데이터 파일에 저장됩니다. 전달이 끝나면 폰에서 `내 표시 비우기`로 지웁니다(안 지우면 AI가 고쳐서 표시가 사라진 뒤에도 폰에는 계속 남아 보입니다).
- 필터 `🚩 검수 표시만`, 씬 목록의 `🚩N`, 현황 줄의 `🚩 검수 표시`로 남은 건수를 봅니다.
- AI·작업자용 명령:
  ```bash
  node tools/review.js --work seohee list [<씬ID>] [--count]          # 표시된 줄 목록 (JSON), --count 는 씬별 개수만
  node tools/review.js --work seohee import 검수목록.json [--dry]       # 복사해 온 목록을 파일에 반영 (- 는 표준입력)
  node tools/review.js --work seohee resolve H1 --ids <id,id> | --rows 22-30 | --all [--note "사유"]   # 고친 줄의 표시 지우기
  ```
  줄 내용은 `scene.js set`으로 고치고, 고친 줄은 `resolve`로 표시를 지웁니다(패치에 `"review":""`를 같이 넣어도 됩니다). 줄을 새로 넣거나 빼야 하는 항목은 아래 `insert`/`delete`로 처리합니다(새가족 등 번호가 이어지는 씬만). 모두 변경 기록에 남아 `scene.js revert`로 되돌릴 수 있습니다.

### AI·작업자용 도구
작품이 하나뿐이면 `--work`를 생략할 수 있고, **둘 이상이면 반드시 지정**해야 합니다. 아래 예시는 `seohee` 기준이며 `--work`와 씬 ID만 바꾸면 다른 작품에도 그대로 씁니다.

```bash
node tools/scene.js --work seohee list                                   # 씬별 행 수·진행률
node tools/scene.js --work seohee get N1 --fields id,korean --limit 20   # 필요한 필드만 조회
node tools/scene.js --work seohee get H13 --empty prompt --fields id,speaker,korean,prompt  # 프롬프트가 빈 행
node tools/scene.js --work seohee get N1 --empty korean --fields id,english   # 한국어가 빈 행
node tools/scene.js --work seohee get H3 --from 3000 --to 3100 --tsv     # 행 번호 범위
node tools/scene.js --work seohee set N1 patch.json --dry                # 수정 미리 검증 (파일 변경 없음)
node tools/scene.js --work seohee set N1 patch.json --note "말투 통일"    # 바뀐 행만 반영 + 수정 사유 기록
node tools/scene.js --work newfamily insert EP1 rows.json --note "사유"   # 줄 추가: [{"after":"앞 줄 ID","speaker":"나레이션","korean":"…"}] (행 번호가 이어지는 씬만)
node tools/scene.js --work newfamily delete EP1 --ids EP1#18 --note "사유" # 줄 삭제 (같은 조건)
node tools/scene.js --work seohee log N1                                 # 변경 묶음 목록 (본문 없이 요약)
node tools/scene.js --work seohee revert N1 --last                       # 가장 최근 변경 되돌리기
node tools/scene.js --work seohee revert N1 --batch b20261111-130500 --ids <id1,id2>   # 특정 묶음(의 일부 행) 되돌리기
```

- `patch.json`: `[{"id":"…","korean":"수정한 대사"}, …]` — 바뀐 필드만 적습니다. 여러 행에 `prompt`를 넣은 배열을 만들어 `set`하면 프롬프트를 한 번에 반영할 수 있습니다.
- 수정 가능 필드: `kind`, `speaker`, `english`, `korean`, `recordingScript`, `prompt`, `memo`, `voice`, `review`(🚩 검수 표시). `id`·`rowNumber`·`phaseId`와 씬 정보는 바꿀 수 없고, 잘못된 ID나 필드가 하나라도 있으면 **아무것도 적용하지 않습니다.**
- 반영하면 변경 기록이 남고(`set` 결과의 `batch`가 묶음 ID), `index.js`의 개수·진행 통계가 자동으로 다시 계산됩니다.
- `revert`는 기록의 수정 전 값으로 복구합니다. 그 뒤에 다른 수정이 있었던 항목은 건드리지 않고 `conflicts`로 알려주며, 일부만 되돌려진 묶음은 `--last`로 남은 항목을 다시 되돌릴 수 있습니다. `--dry`로 미리 확인할 수 있습니다.
- `insert`/`delete`(줄 추가·삭제)는 **행 번호가 1씩 이어지는 씬에서만** 됩니다. 원본 엑셀과 번호가 짝을 이루는 씬(번호가 띄엄띄엄)은 거부합니다. 새 줄 ID는 그 씬의 가장 큰 `파일#번호`+1(위치와 무관하게 고유), 단계는 앞 줄을 따르고, 끝나면 행 번호(`rowNumber`)를 다시 매깁니다(그래서 줄 추가·삭제 뒤에는 이전에 적어 둔 행 번호가 밀릴 수 있으니 줄 ID로 가리킵니다). 변경 기록에는 `+row`/`-row`로 남아 `revert`로 되돌릴 수 있습니다.
- `log`는 기본적으로 본문 없이 요약만 출력합니다(`--detail`을 줘야 수정 전·후가 나옴).

## 프롬프트 선택·일괄 삽입 (구현됨)

`recordingScript`는 성우나 음성 모델이 읽을 **녹음용 대본**이고, `prompt`는 감정·톤·속도 등을 지시하는 **별도 프롬프트**입니다. 두 값은 합치지 않습니다. 이 기능은 대본이 있는 행에 템플릿 프롬프트를 한꺼번에 넣고 지우기 위한 것입니다.

**화면 사용 순서** (대사집 화면, 필터 줄 아래의 선택 줄)

1. 표 맨 앞 체크박스로 행을 고릅니다. **`recordingScript`가 있는 행만** 선택할 수 있고 없는 행은 체크박스가 비활성입니다. 표 머리 체크박스는 화면에 표시된 대본 행 전체를 켜고 끕니다.
2. 선택 줄의 버튼으로 한 번에 고를 수도 있습니다. 누르면 선택이 그 범위로 **바뀝니다**.
   - `표시된 행 전체`: 현재 필터·단계 탭에 보이는 행만 (숨겨진 행 제외)
   - `현재 단계 전체`: 현재 단계의 모든 행 (**필터로 숨겨진 행 포함**, 단계 탭을 고른 경우에만)
   - `현재 씬 전체`: 씬의 모든 행 (**필터·단계와 관계없이 숨겨진 행 포함**)
   - 선택 개수는 항상 `선택 N행 (표시 a · 필터로 숨김 b)`로 보입니다. **필터를 바꿔도 선택은 유지되고, 씬을 바꾸면 해제됩니다.**
3. 오른쪽 `프롬프트 관리/삽입` 패널(항상 열려 있음)에서 템플릿 버튼을 하나 이상 켜고 작업을 정합니다. 여러 개를 켜면 누른 순서대로 `[내용1, 내용2, 내용3]` 형식(쉼표+공백 구분, 대괄호)으로 합쳐집니다.
   - `빈 칸만 적용`: 이미 프롬프트가 있는 행은 그대로 둠
   - `기존 값 교체`: 선택 행을 모두 이 템플릿으로 바꿈 — 기존 프롬프트가 사라지는 행 수를 보여 주고 **확인란을 체크해야** 진행됨
   - `선택 행 프롬프트 삭제`: 프롬프트가 있는 행만 지움 — 대상 행 수를 보여 주고 확인란 체크 필요
4. (서버 없이) `AI 작업 요청 복사`를 눌러 채팅에 붙여넣으면 AI가 `tools/prompt.js` 명령을 실행해 **저장소 데이터에 반영**합니다(페이지는 읽기 전용이라 파일을 직접 바꾸지 않고, 브라우저 로컬 수정도 건드리지 않습니다). 반영 뒤 페이지를 새로고침하면 `프롬프트` 열에 나타납니다.

**집에서 직접 고칠 때: 저장 서버** — 녹음을 돌려 보고 프롬프트를 직접 고치고 싶을 때는 폴더의 `저장서버 켜기.bat`을 더블클릭하세요(또는 `node tools/server.js --open`). 브라우저가 `http://127.0.0.1:8787/`로 열리고, 상단에 `저장 서버 연결됨`이 보이면 아래가 켜집니다.
- `프롬프트 관리/삽입`의 `지금 적용 (파일에 저장)` → 선택한 행에 바로 채우거나 지웁니다. AI에게 붙여넣는 단계가 필요 없습니다.
- 페이지에는 템플릿 추가·수정 기능이 없습니다. 템플릿은 `prompts.js`를 직접 고치거나 `tools/prompt.js template set|remove`로 관리합니다(이미 적용한 행은 바뀌지 않음).
- 서버는 이 컴퓨터(127.0.0.1)에서만 열리고 다른 사이트의 저장 요청은 거부합니다. 창을 닫으면 꺼지고, 그러면 페이지는 예전처럼 읽기 전용(브라우저 로컬 수정)이 됩니다. 되돌리기는 AI에게 요청하거나 `scene.js revert`를 씁니다.
- **왜 서버(.bat)가 필요한가:** 브라우저 페이지는 보안상 PC의 파일을 직접 쓸 수 없어서, 파일에 대신 써 주는 도우미가 필요합니다. 서버가 꺼져 있으면 `지금 적용` 버튼이 보이지 않고 `AI 작업 요청 복사`만 있으며, 그 버튼은 요청 문장을 복사할 뿐 파일에는 아무것도 저장하지 않습니다. 저장이 되는지는 상단의 `저장 서버 연결됨` 표시로 확인합니다.
- AI에게 요청하는 방식이면 서버는 필요 없습니다(AI가 직접 파일에 씀). 서버는 AI 없이 집에서 화면으로 직접 고치고 싶을 때만 켜는 선택 사항입니다.
- 회사 PC나 AI에게 맡길 때는 서버 없이 `AI 작업 요청 복사`를 씁니다. 저장된 파일은 GitHub Desktop에서 커밋·푸시해야 다른 PC에 반영됩니다.

복사되는 요청은 이런 모양입니다(행 번호는 행 번호 범위, 대본이 없는 행은 도구가 알아서 건너뜀).

```
프롬프트 일괄 적용 요청
- 작품 seohee · 씬 N1 · 선택 12행 (실제 변경 예정 10행)
- 템플릿 「일상 대화」(daily) · 빈 칸만 적용

node tools/prompt.js --work seohee apply N1 --template daily --mode fill --rows 22-30,35
node tools/prompt.js --work seohee apply N1 --template soft,shy --mode fill --rows 22-30   # 여러 템플릿: 쉼표 순서대로 [내용1, 내용2] 형식
```

**AI가 할 일:** 요청 안의 명령을 그대로 실행하고 결과 JSON(`changedRows`, `skippedHasValue`, `batch` 등)을 사용자에게 알려줍니다. 되돌릴 때는 `node tools/scene.js --work <작품ID> revert <씬ID> --last`입니다(프롬프트 변경도 같은 변경 기록에 남음). 먼저 확인하고 싶으면 명령 끝에 `--dry`를 붙입니다.

**템플릿 관리:** 템플릿은 작품별 `works/<작품ID>/data/prompts.js`에 있으며 페이지 목록에 그대로 나타납니다. 분류 탭도 작품마다 정할 수 있습니다: `prompts.js`의 `"groups":[["키","탭 이름"], …]` (없으면 기본 탭 행위·단계·흥분도·추가 감정, `suikoden1`은 감정·말투·속도·호흡·상황). **윗줄 구분 탭(`일반` / `행위`)**은 `prompts.js`에 `"sections":[["general","일반"],["act","행위"]]`를 두고 `groups` 항목의 세 번째 값으로 소속을 적으면 켜집니다(예: `["gen_emotion","감정","general"]`). 구분 탭을 누르면 그 구분의 분류 탭만 보이고, 켜 둔 템플릿은 구분을 넘어 유지됩니다(구분 탭 옆 숫자 = 그 구분에서 켠 개수). `sections`가 없는 작품은 예전처럼 분류 탭만 보입니다. **현재 서희·새가족에 적용**: `일반`(서희: 감정·숨·소리 / 새가족: 인물·감정·숨·소리·상황) 과 `행위`(행위·단계·흥분도·추가 감정 — 서희의 기존 관계 템플릿 59개가 여기에 있고, **새가족에도 같은 59개를 그대로 복사해 둠(2026-11-13)**; 이후 두 작품의 템플릿은 서로 독립이라 한쪽을 고쳐도 다른 쪽은 안 바뀜). 새가족의 일반 템플릿은 ElevenLabs 스타일 영어 태그 초안이라 사용하면서 다듬을 것(행위 쪽은 서희 것을 복사한 상태). 추가·수정·삭제는 채팅으로 AI에게 요청하고, AI는 아래 명령을 씁니다. 지금 들어 있는 6개(일상 대화·밝고 경쾌하게·부드럽게 속삭이듯·나레이션 담담하게·놀람·당황·쓸쓸하고 가라앉은 톤)는 **임의의 예시**이니 실제 쓸 내용으로 바꾸세요.

```bash
node tools/prompt.js --work seohee templates                                            # 템플릿 목록
node tools/prompt.js --work seohee template set daily --name "일상 대화" --text "프롬프트 내용"   # 추가·수정
node tools/prompt.js --work seohee template remove daily
node tools/prompt.js --work seohee apply N1 --template daily --phase N1-P1 --mode replace --dry  # 단계 전체 교체 미리보기 (--rows / --phase / --all 중 하나)
node tools/prompt.js --work seohee clear N1 --all                                       # 씬의 대본 행 프롬프트 모두 삭제
```

`--note "사유"`를 생략하면 `프롬프트 빈 칸 적용: <템플릿 이름>` 같은 기본 사유가 기록됩니다. 템플릿에 변수(화자 이름 등)를 넣는 기능은 아직 없고, 문장 그대로 `prompt`에 들어갑니다.

### 작품: 서희 (seohee)

영어 번역본을 한국어로 번역·검수하는 작품입니다. 검수본 `translated_script_final_20261110_h10_h12_rechecked.xlsx` 기준 **10,917행, 60개 씬**(`N1`~`N37` 일반씬, `H1`~`H23` 행위씬)이고, 행 `id`는 `파일명.ks#줄번호`, `rowNumber`는 엑셀 행 번호입니다. 줄 추가·삭제(`insert`/`delete`)는 엑셀 행 번호와 짝이 있어서 이 작품에서는 쓰지 않습니다.

#### 번역·대사 검수 기준

##### 기본 원칙

- 번역 흐름은 **일본어 원문 → 영어 번역 → 한국어**입니다. 영어 문장을 그대로 직역하지 말고 일본식 표현과 어순, 장면 문맥을 고려해 자연스러운 한국어로 재구성합니다.
- 현재 데이터에는 일본어 원문 열이 없으므로, 영어 원문과 장면의 앞뒤 흐름을 기준으로 일본식 번역투를 추정해 수정합니다. 원문 대사는 비교할 수 있도록 보존하고 한국어 대사만 고칩니다.
- 장면의 상황, 앞뒤 문맥, 인물 관계와 성격을 먼저 파악합니다. 원문의 의미를 빠뜨리거나 원문에 없는 내용을 과도하게 추가하지 않습니다.
- 인물 대사는 자연스러운 구어체로, 나레이션은 끊기지 않는 서술체로 작성합니다. 번역투 어순, 주어·목적어 누락, 문장 중단을 특히 확인합니다.
- 서희뿐 아니라 준형·나레이션·부모님·주변 인물까지 모든 화자를 검수합니다.
- 일반씬은 자연스러운 일상 대화를 우선합니다. 행위씬은 도입·전희·주요 행위·절정 전·절정·사정·사정 후의 단계와 감정 변화에 맞춰 표현 강도를 조절합니다.
- 첫 행위씬 이후 경험이 쌓일수록 서희의 말투는 조금씩 대담하고 적극적으로 변합니다. 다만 갑자기 성격이 바뀌거나 원문보다 지나치게 노골적인 표현을 임의로 넣지 않습니다.
- 직접적인 단어는 문맥상 필요하면 사용할 수 있지만, 전체적으로는 조금 순화된 수준을 유지합니다.
- 서희의 행위씬 한국어 대사를 수정하면 `recordingScript`에도 같은 내용을 반영합니다. 현재 준형은 음성 대상에서 제외하며, 나머지 인물은 음성 대상이라는 점을 고려합니다.
- `prompt`는 녹음·음성 생성용 지시문을 나중에 씬 단위로 일괄 입력하기 위한 별도 필드입니다. 대사나 녹음용 대본과 섞지 않습니다.

##### 스크립트 문체·윤문 기준 (나레이션 중심)

- 이 작품의 문체 목표는 화려한 문장을 과시하는 것이 아니라, **준형의 시점에서 장면이 자연스럽게 이어지고 독자가 감각과 감정의 변화를 바로 따라갈 수 있게 하는 것**입니다. 번역의 정확성만 맞추지 말고 읽는 흐름과 몰입감까지 다듬습니다.
- 나레이션은 기본적으로 **준형의 1인칭 현재형·제한 시점**을 유지합니다. 준형이 직접 보고 듣고 느끼거나 추측할 수 있는 내용만 씁니다. 서희의 속마음을 확정적으로 단정하지 말고, 표정·행동·말투를 근거로 `~인 듯하다`, `~하려는 모양이다`처럼 표현합니다.
- 준형의 나레이션에서는 서희를 주로 `누나`라고 부릅니다. 영어 원문의 `she`를 따라 `그녀`를 반복하지 않습니다. 반대로 모든 문장을 `누나는`으로 시작하지 말고 주어 생략, 행동 선행, 감각 선행 등으로 문장 구조를 바꿉니다.
- 행동을 순서대로 옮겨 적는 **동작 보고서식 나열**을 피합니다. 가능하면 `상대의 행동 → 준형이 느낀 감각 → 즉각적인 생각·감정`이 한 흐름으로 이어지게 씁니다. 나레이션 한 줄은 장면 진행, 감각 전달, 심리 노출, 관계 표현 중 최소 하나의 역할을 해야 합니다.
- 감정 이름을 바로 설명하기보다 몸의 반응과 행동으로 보여 줍니다. `당황했다`, `흥분했다`, `기분이 좋다`만 반복하지 말고 시선이 멎는 지점, 호흡이 흐트러지는 순간, 말이 막히는 이유, 망설이다가 결국 선택하는 행동처럼 구체적으로 씁니다.
- 감각 묘사는 장면에 필요한 것만 골라 **소리·온기·촉감·냄새·무게감·거리·움직임의 속도**를 섞습니다. 한 문장에 감각을 모두 넣는 식의 과잉 묘사는 피하고, 같은 감각 표현이 연속해서 나오지 않게 합니다.
- `침을 삼킨다`, `얼굴이 뜨거워진다`, `머리가 하얘진다`, `심장이 뛴다`, `시선을 뗄 수 없다`, `정신을 차릴 수 없다` 같은 익숙한 반응은 편리하다는 이유로 반복하지 않습니다. 한 장면에서 이미 썼다면 다음에는 구체적인 행동·생각·감각으로 바꿉니다.
- 문장 호흡은 장면 속도에 맞춥니다. 일상 장면은 한두 문장 안에서 상황과 감정을 부드럽게 연결하고, 긴장하거나 감각이 고조되는 부분은 짧은 문장으로 속도를 높입니다. 반대로 모든 줄을 짧게 끊거나 쉼표로 여러 동작을 길게 이어 붙이지 않습니다.
- 비유와 수식어는 구체적인 감각을 선명하게 만들 때만 사용합니다. 원문에 없는 거창한 비유, 과장된 문학 표현, 상투적인 미사여구를 덧붙이지 않습니다. 직접적인 표현도 장면과 준형의 인식에 필요한 만큼만 쓰며, 자극적인 단어를 늘리는 것으로 필력을 대신하지 않습니다.
- 일반씬에서는 익숙한 가족 관계 속 미묘한 의식과 망설임을 중심으로 쓰고, 행위씬에서는 단계에 따라 나레이션의 초점을 바꿉니다. 초반은 기대·긴장·주저함, 중반은 동작과 감각의 변화, 절정 전후는 좁아지는 인식과 흐트러지는 호흡, 마무리는 관계와 여운이 드러나게 합니다. 처음부터 끝까지 같은 강도로 밀어붙이지 않습니다.

  2. **타협** (소영과의 거래, 2부~): 선을 넘은 걸 정당화("시키는 대로 하는 것") → 호흡 세기가 엉킴, 규칙·루틴 묘사와 자기합리화 문장, 시선이 훔쳐보기로 바뀜. (2부 끝이 이 단계로 넘어가는 지점)
  3. **갈망** (중반): 시키지 않아도 기다리는 자신을 발견, 죄책감과 욕망이 공존 → 주어가 "누나가"에서 "내가"로 이동, 호흡 세기를 포기하거나 잊음, 시선이 응시로 바뀜.
  4. **능동** (후반): 원하는 걸 알고 상대의 의도도 더 빨리 읽음 → 문장이 길고 안정됨, 상대의 반응을 읽는 문장이 늘고 죄책감은 짧은 여운으로만 남음.
- **죄책감은 사라지는 게 아니라 모양이 바뀝니다**: "들키면 안 된다" → "구해 준 가족에게 빚졌다" → "받은 만큼 돌려주고 싶다 / 아무도 못 가져가게 하고 싶다(소유욕·질투)". 그래야 대담해져도 감정이 평평해지지 않습니다.
- **모티프의 변화**: 호흡 세기는 통한다(1부 초반) → 엉킨다(2부) → 세지 않게 된다 → 마지막에는 상대가 대신 숨을 세어 주는 식으로 뒤집기. 시선은 피함 → 훔쳐봄 → 응시 → 마주 봄. 마음속 호칭도 달라질 수 있음(예: 동생 → 미소).
- **인물마다 다른 경로**: 엄마는 보호받던 존재라 죄책감이 가장 커서 가장 늦게·조심스럽게. 소영은 주도권을 쥔 쪽에서 시작해 주인공이 처음 주도권을 가져가는 전환점을 만들 수 있음. 미소는 가장 무구해서 죄책감이 가장 크게 걸리고, 오히려 미소가 선을 정하는 쪽으로 가면 다른 두 사람과 차이가 남.
- **주의**: 여성 인물이 주인공의 변화를 위한 도구로 보이지 않게 각자의 의도가 나레이션에 어렴풋이 비치게 함(서희 기준의 "의도를 단정하지 않고 표정·행동으로 읽는다"와 같음). 한 편에 한 단계씩만 움직이고, 나레이션도 한 번에 바꾸지 않고 서서히 바꿈.

#### 프롬프트 제작 설계 (ElevenLabs, 2026-11-13)

## 아이디어 메모 (미구현)

- **자동 재생 검수:** 대사·CG·음성이 갖춰지면 게임을 직접 실행하지 않고도 씬을 자동으로 재생해서, 작업이 제대로 됐고 잘 어울리는지 확인하는 기능. (검수용 아이디어이며 아직 설계·구현 전)
- **서버 없이 저장 (써 보고 결정):** 지금은 파일 저장에 서버(`저장서버 켜기.bat`)가 필요한데 번거롭다는 의견이 있었습니다. 대안은 크롬·엣지의 폴더 연결 기능(File System Access API)으로, 페이지에서 프로젝트 폴더를 한 번 허용하면 서버 없이 페이지가 직접 파일에 씁니다. 크롬·엣지에서만 되고, 파일로 직접 연 페이지에서도 되는지는 아직 확인 전입니다(집에서 확인 필요). 브라우저에만 저장하는 방식은 가장 쉽지만 컴퓨터·브라우저마다 따로 저장되고 GitHub와 AI에는 반영되지 않습니다. 템플릿 목록은 집에서만 고치는 것으로 정했으므로 현재 서버 방식을 유지하고, 써 보면서 불편하면 폴더 연결 방식으로 바꿉니다.
- **자동 점검:** 음성 체크(✓)와 실제 파일의 일치 여부, 파일 이름·ID 연결 오류, 음성 길이 이상, CG 누락 등을 목록으로 알려주는 기능.

## 저장소·환경 메모

- 음성·CG 폴더는 `.gitignore`로 제외됩니다 (`voice/`, `audio/`, `cg/`). 실제 폴더 이름이 다르면 추가하세요.
- CG 기본 폴더는 저장소와 같은 상위 폴더의 `CG_extracted_20261111/patched_png`입니다. 다른 위치는 `PROJECT_H_CG_DIR` 환경 변수로 지정한 뒤 `node tools/server.js`를 실행하세요. CG는 `file://`로 직접 연 페이지가 아니라 저장 서버 주소에서 표시됩니다.
- Windows PC에서 `git`이 PATH에 없을 수 있습니다. GitHub Desktop 안의 git(`%LOCALAPPDATA%\GitHubDesktop\app-*\resources\app\git\cmd\git.exe`)을 쓰세요. 폴더 소유자가 달라 "dubious ownership" 오류가 나면 전역 설정을 바꾸지 말고 명령마다 `-c safe.directory=<경로>`를 주세요.
- 검색 엔진 수집 방지를 위해 `noindex` 메타 태그가 적용되어 있습니다.
